1.5 Business Rules and Stated Assumptions

  1. Single Vehicle Invariant: A single parking slot can accommodate exactly one vehicle at any time. A slot occupied by a vehicle cannot accept another allocation until explicitly released.
  2. Unique Ticket Identifier: Ticket sequence counters are monotonic and never reused or decremented during the lifetime of the application.
  3. Ceiling Billing Rule: "Every started hour is charged in full." Parking stays are converted to billable hours via the mathematical ceiling function: 1 min to 60 mins = 1 hour; 61 mins to 120 mins = 2 hours.
  4. Pass Privilege Waiver: Students and staff members presenting a valid monthly parking pass are granted 100% waiver on base parking duration fees (Rs 0.00). Auxiliary EV charging consumption remains billable.
  5. Plate Equivalence: Vehicle equivalence is strictly governed by state license plate registration numbers, evaluated in a case-insensitive manner ("TN01AB1111".equalsIgnoreCase(...)).

2.2 Array Structure: Jagged Arrays vs 1D / Regular 2D Arrays

The facility layout is formally represented using a jagged 2D array of String pointers: 

// slots[floor][slot] holds a vehicle number, or null if the slot is free
private final String[][] slots;

public ParkingFacility(int[] slotsPerFloor) {
    slots = new String[slotsPerFloor.length][];
    for (int f = 0; f < slotsPerFloor.length; f++) {
        slots[f] = new String[slotsPerFloor[f]];
    }
}

Why Jagged Arrays (String[][]) Represent Physical Reality Best:

  • Asymmetric Floor Architecture: Real-world parking buildings feature unequal capacities per floor. The Ground Floor ($f=0$) accommodates entrance ramps, security cabins, automated barriers, and EV chargers, leaving room for fewer parking bays (e.g., 20 slots). Upper levels ($f=1, 2, 3$) feature wide open spans holding 50 or 100 bays.
  • Elimination of Wasted Memory: In a uniform rectangular matrix new String[floors][maxSlots], every floor allocates an array sized to the maximum capacity. If Floor 0 has 20 slots and Floor 4 has 100 slots, 80 pointers on Floor 0 sit permanently unused as nulls. A jagged array allocates exactly slotsPerFloor[f] pointers per row, optimizing memory.

2.3 Type Conversion and Casting Pitfalls: Integer Division vs Ceiling

The SIMATS assignment brief specifies: "Every started hour is charged in full" (i.e., mathematical ceiling $\lceil rac{ ext{minutes}}{60} ceil$).

Hazard 1: The Integer Division Truncation Hazard

// FLAWED IMPLEMENTATION:
int hours = minutes / 60; // Truncates remainder towards zero!
double fee = hours * ratePerHour;

Because both minutes and 60 are integer literals, Java executes integer division:

  • A customer parked for 15 minutes: 15 / 60 = 0 hours $ ightarrow$ Fee = Rs 0.00 (Vehicle parks free of charge!).
  • A customer parked for 65 minutes: 65 / 60 = 1 hour $ ightarrow$ Fee = Rs 30.00 instead of Rs 60.00 (Loss of 50% revenue).

Hazard 2: The Ineffective Float-Cast Hazard

// FLAWED IMPLEMENTATION:
int hours = (int) Math.ceil(minutes / 60); // Integer division executes BEFORE Math.ceil()!

For minutes = 65, 65 / 60 evaluates to integer 1 before being widened to 1.0. Math.ceil(1.0) returns 1.0, failing to round up.

The Robust Design Solution: Pure Integer Arithmetic Ceiling

Our design implements pure integer arithmetic without floating-point conversion: 

// PRODUCTION INTEGER CEILING FORMULA:
int hours = (minutes == 0) ? 0 : (minutes + 59) / 60;
double fee = hours * ratePerHour();

Mathematical Proof: For any positive integer $m$: $$\lceil m / 60 ceil = \lfloor (m + 59) / 60 floor$$ - For $m = 1$: $(1 + 59) / 60 = 60 / 60 = 1$ hour. - For $m = 59$: $(59 + 59) / 60 = 118 / 60 = 1$ hour. - For $m = 60$: $(60 + 59) / 60 = 119 / 60 = 1$ hour. - For $m = 61$: $(61 + 59) / 60 = 120 / 60 = 2$ hours. This eliminates IEEE 754 precision loss while guaranteeing mathematical exactness across all durations.

3.1 Algorithmic Pseudocode (SIMATS Engineering Standard)

Following the SIMATS Engineering - Standard for Algorithmic Pseudocode, the decision and looping algorithms for the two core operations are specified below prior to implementation. 

ALGORITHM AllocateSlot(slots, vehicleNo)
    INPUT: 
        slots       : Jagged 2D array of String representing floors and slot assignments
        vehicleNo   : String containing vehicle license plate number
    OUTPUT: 
        Array [floor, slot] of allocated coordinates, or NULL if facility is full

BEGIN
    FOR floorIndex ← 0 TO LENGTH(slots) - 1 DO
        FOR slotIndex ← 0 TO LENGTH(slots[floorIndex]) - 1 DO
            IF slots[floorIndex][slotIndex] IS NULL THEN
                slots[floorIndex][slotIndex] ← vehicleNo
                RETURN [floorIndex, slotIndex]       // Early exit terminates search immediately
            END IF
        END FOR
    END FOR

    RETURN NULL                                      // Facility is completely full
END
ALGORITHM ReleaseSlot(slots, floor, slot)
    INPUT: 
        slots : Jagged 2D array of String representing facility slots
        floor : Integer representing target floor level
        slot  : Integer representing target slot index
    OUTPUT: 
        Boolean: TRUE if successfully released, FALSE if invalid coordinate or already free

BEGIN
    // Step 1: Validate floor boundary
    IF floor < 0 OR floor >= LENGTH(slots) THEN
        RETURN FALSE
    END IF

    // Step 2: Validate slot boundary on target floor
    IF slot < 0 OR slot >= LENGTH(slots[floor]) THEN
        RETURN FALSE
    END IF

    // Step 3: Check if slot is already empty
    IF slots[floor][slot] IS NULL THEN
        RETURN FALSE
    END IF

    // Step 4: Deallocate slot
    slots[floor][slot] ← NULL
    RETURN TRUE
END

3.2 Complete the Code Implementation: ParkingFacility.java

Below is the complete, working code fulfilling TODO 1 and TODO 2 without modifying the given main() driver: 

public class ParkingFacility {
    // slots[floor][slot] holds a vehicle number, or null if the slot is free
    private final String[][] slots;

    public ParkingFacility(int[] slotsPerFloor) {
        slots = new String[slotsPerFloor.length][];
        for (int f = 0; f < slotsPerFloor.length; f++) {
            slots[f] = new String[slotsPerFloor[f]];
        }
    }

    /** Returns {floor, slot} of the first free slot, or null if it is full. */
    public int[] allocate(String vehicleNo) {
        // TODO 1: Search floor by floor and slot by slot, place vehicleNo in the first
        // free slot and return {floor, slot}
        for (int f = 0; f < slots.length; f++) {
            for (int s = 0; s < slots[f].length; s++) {
                if (slots[f][s] == null) {
                    slots[f][s] = vehicleNo;
                    return new int[]{f, s}; // Early return on first available slot
                }
            }
        }
        return null; // Facility full
    }

    /** Frees a slot. Returns false if the position is invalid or already free. */
    public boolean release(int floor, int slot) {
        // TODO 2: Validate floor and slot, free the slot and return true; otherwise return false
        if (floor < 0 || floor >= slots.length) {
            return false;
        }
        if (slot < 0 || slot >= slots[floor].length) {
            return false;
        }
        if (slots[floor][slot] == null) {
            return false;
        }
        slots[floor][slot] = null;
        return true;
    }

    public static void main(String[] args) {
        // floor 0 has 2 slots, floor 1 has 1 slot
        ParkingFacility p = new ParkingFacility(new int[]{2, 1});
        System.out.println(java.util.Arrays.toString(p.allocate("TN01AB1111")));
        System.out.println(java.util.Arrays.toString(p.allocate("TN02CD2222")));
        System.out.println(java.util.Arrays.toString(p.allocate("TN03EF3333")));
        System.out.println(java.util.Arrays.toString(p.allocate("TN04GH4444")));
        System.out.println(p.release(0, 1) + " " + p.release(0, 1) + " " + p.release(5, 0));
        System.out.println(java.util.Arrays.toString(p.allocate("TN04GH4444")));
    }
}

4.1 Constructor Taxonomy and Constructor Chaining (this())

To prevent code duplication, enforce object state invariants, and support diverse instantiation workflows, our system employs constructor overloading coordinated through master constructor chaining: 

public class ParkingTicket {
    private final String ticketId;
    private final String regNo;
    private final int floor;
    private final int slot;
    private final LocalDateTime entryTime;
    private final boolean hasMonthlyPass;

    // Minimal Constructor: Chains to master constructor with default pass status (false)
    public ParkingTicket(String regNo, int floor, int slot) {
        this(regNo, floor, slot, false, LocalDateTime.now());
    }

    // Overloaded Constructor: Chains with explicit pass status and current time
    public ParkingTicket(String regNo, int floor, int slot, boolean hasMonthlyPass) {
        this(regNo, floor, slot, hasMonthlyPass, LocalDateTime.now());
    }

    // Master Parameterized Constructor: Enforces defensive parameter validation
    public ParkingTicket(String regNo, int floor, int slot, boolean hasMonthlyPass, LocalDateTime entryTime) {
        if (regNo == null || regNo.isBlank()) {
            throw new IllegalArgumentException("Vehicle registration cannot be blank.");
        }
        if (floor < 0 || slot < 0) {
            throw new IllegalArgumentException("Parking coordinates must be non-negative.");
        }
        this.ticketId = "TICK-" + (++ticketCounter);
        this.regNo = regNo.trim().toUpperCase();
        this.floor = floor;
        this.slot = slot;
        this.hasMonthlyPass = hasMonthlyPass;
        this.entryTime = (entryTime != null) ? entryTime : LocalDateTime.now();
    }

    // Copy Constructor: Used for duplicate ticket re-issuance without state corruption
    public ParkingTicket(ParkingTicket original) {
        if (original == null) throw new IllegalArgumentException("Original ticket cannot be null.");
        this.ticketId = original.ticketId + "-DUP";
        this.regNo = original.regNo;
        this.floor = original.floor;
        this.slot = original.slot;
        this.hasMonthlyPass = original.hasMonthlyPass;
        this.entryTime = original.entryTime; // LocalDateTime is immutable (thread-safe shallow copy)
    }
}

4.2 Memory Storage Model: JVM Stack Frames vs Heap Memory

When ParkingTicket t = new ParkingTicket("TN01AB1111", 0, 1); executes:

  • JVM Call Stack: The local reference variable t is allocated inside the current thread's stack frame. It occupies 8 bytes (under 64-bit JVM with -XX:+UseCompressedOops, 4 bytes). Primitive parameters (floor = 0, slot = 1) are pushed directly into operand registers/stack frame slots.
  • JVM Heap Space: The new operator dynamically allocates a contiguous memory block on the heap. This block houses:
    1. Object Header (12–16 bytes): Mark Word (hash code, GC generation age, locking flags) and Klass Word pointing to ParkingTicket.class metadata in Metaspace.
    2. Instance Fields: 8-byte pointer to the String literal "TN01AB1111" in the String constant pool, 4-byte floor, 4-byte slot, 1-byte hasMonthlyPass, 8-byte reference to LocalDateTime.
    3. Padding (0–7 bytes): Padding to align the total object size to an 8-byte word boundary.

5.2 The Multi-Gate Collision Hazard: Why Instance Counters Fail

Architectural Scenario:
"The ticket counter is a static variable. If it were made an instance variable of ParkingFacility, what would happen when the university runs two facilities (North and South gates)?"

If ticketCounter were an instance variable of ParkingFacility: 

// ARCHITECTURAL FLAW:
ParkingFacility northGate = new ParkingFacility(layout1); // counter initialized to 0
ParkingFacility southGate = new ParkingFacility(layout2); // counter initialized to 0

northGate.parkVehicle(car1); // Issues ticket "TICK-1"
southGate.parkVehicle(car2); // Issues ticket "TICK-1" <-- CATASTROPHIC TICKET COLLISION!

Because each facility instance allocates its own private counter on the heap, both gates simultaneously issue TICK-1. When car 2 exits through the north gate, the automated barrier finds a duplicate or mismatched record, corrupting revenue logs and trapping vehicles.

Resolution: The sequence generator is declared static (or managed via AtomicInteger), ensuring a single centralized sequence stored in class Metaspace shared across all facility instances and threads.

5.3 Object Lifecycle and Garbage Collection (GC) Eligibility

A ParkingTicket progresses through distinct JVM lifecycle stages:

  1. Instantiation: Memory allocated in Heap Eden space; reference assigned to t on Stack and stored in activeTickets map.
  2. Active Lifetime: Object remains reachable via active roots (facility lookup collections). Protected from garbage collection.
  3. Checkout & Nullification: Upon vehicle departure, activeTickets.remove(regNo) removes the pointer. When local reference t goes out of scope, the ticket has zero active GC roots.
  4. Garbage Collection: During the next minor GC cycle, the generational garbage collector detects the orphaned object in Eden/Survivor space and reclaims its memory with zero leak.

5.4 Parameter Passing Semantics in Java

Java is strictly pass-by-value at all times:

  • For primitive parameters (int minutes), a bitwise copy of the value is pushed onto the called method's stack frame. Modifications inside the method have zero effect on the caller's variable.
  • For object references (Vehicle v), a copy of the 64-bit heap memory address pointer is passed by value. Modifying the object's internal fields (e.g. through mutators) alters the shared heap object, but reassigning the reference (v = new Car(...)) only overwrites the local copy without altering the caller's reference.

7.1 Overriding Strategy & Specialized Behavioral Contracts

Subclasses customize base behavior through method overriding:

  • ratePerHour(): Declared protected abstract in Vehicle. TwoWheeler overrides it to return 10.0; Car overrides it to return 30.0.
  • calculateFee(int minutes): Implemented as a template method in Vehicle. Subclasses inherit the standard duration ceiling logic while injecting their specialized hourly tariff dynamically.

7.2 The @Override Annotation Contract and Rules

The @Override annotation provides compile-time verification ensuring:

  1. Exact Method Signature: Method name, parameter types, and parameter order must match the superclass exactly. Accidental overloads (e.g. ratePerHour(int x)) trigger compile-time errors.
  2. Covariant Return Types: The overridden method may return a subtype of the superclass return type, but never a widened or unrelated type.
  3. Access Privileges: An overriding method can widen visibility (e.g., protected to public), but cannot restrict it (e.g., public to private).

7.3 Strategic Utilization of the final Keyword

  • private final String regNo: Guarantees reference and license plate immutability once constructed. Prevents unauthorized plate tampering.
  • public final String getRegNo(): Declaring getters final prevents malicious subclasses from altering the returned identity string.
  • Sealed Algorithms: Core security checks (such as monthly pass cryptographic validation) can be sealed with final to ensure uniform enforcement across all child classes.

10.3 Autoboxing Hazards & The Integer Caching Trap

Java provides automatic conversion between primitive types and their corresponding wrapper objects (e.g. int $\leftrightarrow$ Integer). However, unmanaged autoboxing introduces subtle runtime hazards:

Hazard 1: The Integer Caching Trap (== vs .equals())

Integer slotA = 100;
Integer slotB = 100;
System.out.println(slotA == slotB); // Prints TRUE (IntegerCache pool: -128 to 127)

Integer slotX = 200;
Integer slotY = 200;
System.out.println(slotX == slotY); // Prints FALSE! Distinct heap objects!

The JVM caches Integer instances in the range $[-128, 127]$. For values above 127 (e.g. slot 200 in large facilities), autoboxing calls new Integer(200), creating distinct heap objects. Using == tests memory reference identity rather than numerical value, causing false coordinate rejections.
Design Rule: Always use primitive int for coordinates, or use .equals() for object comparisons.

Hazard 2: NullPointerException on Unboxing

Integer billableHours = null; // Unassigned variable
int total = billableHours * 30; // CRASHES: NullPointerException on implicit intValue() invocation!

14. Comprehensive Viva Voce Defense & Verification Guide

  1. Why is a jagged array preferred over a standard 2D rectangular array for parking floors?
    Answer: Parking facilities feature asymmetric structural layouts. The ground floor accommodates gates, payment booths, and chargers, resulting in fewer standard parking bays (e.g. 20 slots), while upper floors feature wide spans (e.g. 100 slots). A rectangular matrix String[5][100] forces all floors to allocate 100 pointers, wasting dozens of unused null references per floor. A jagged array String[f] = new String[slotsPerFloor[f]] sizes each floor to exact capacity, eliminating memory waste.
  2. Explain why integer division minutes / 60 causes revenue loss, and how your code fixes it.
    Answer: Java integer division truncates remainders towards zero. A 15-minute stay evaluates to 15 / 60 = 0 hours (unauthorized free parking), and a 65-minute stay evaluates to 65 / 60 = 1 hour (losing 1 hour of fee). Our code resolves this using pure integer arithmetic ceiling: (minutes == 0) ? 0 : (minutes + 59) / 60, which maps 1–60 mins to 1 hr and 61–120 mins to 2 hrs without floating-point inaccuracy.
  3. Why does new Car("TN02B2").equals(new ElectricCar("TN02B2")) print true in Task 8?
    Answer: Because Vehicle.equals(Object o) performs an instanceof Vehicle check and compares license plates via regNo.equals(...). Since ElectricCar extends Car, which extends Vehicle, both share the exact same registration string. In automated parking and civil transport, vehicle legal identity is uniquely anchored to its license plate, so two entries for the same plate must be recognized as identical.
  4. Why must hashCode() be overridden whenever equals() is overridden?
    Answer: Hash-based collections (like HashSet and HashMap) use hashCode() to determine which bucket an object belongs to. If hashCode() is not overridden, two objects that are equal according to equals() will receive distinct identity hash codes from Object.hashCode(). They will land in different buckets, causing HashSet to store duplicate vehicle records.
  5. Why should the ticket sequence counter be static rather than an instance variable?
    Answer: An instance variable would reset to its initial value for every new ParkingFacility object. If the campus operates North and South entrance gates, both facilities would simultaneously issue TICK-1 to different vehicles, causing catastrophic primary key collisions upon exit. Making the counter static ensures a single sequence shared across all gates.
  6. What is the difference between an abstract class and an interface in your system?
    Answer: Vehicle is an abstract class because it models core identity and state (private final String regNo), provides constructor enforcement, and contains template methods. Chargeable is an interface because it models an orthogonal capability (EV charging) that applies only to certain vehicles, enabling multiple inheritance of type.
  7. Why does dynamic method dispatch execute in $O(1)$ time?
    Answer: The JVM compiler assigns every virtual method a fixed index in the class virtual method table (vtable). At runtime, invoking v.calculateFee(...) dereferences the object header to find its vtable, jumps to the pre-indexed slot, and executes the target method in a single machine instruction without evaluating conditional branches.
  8. Explain the Integer caching trap and why wrapper autoboxing can be dangerous.
    Answer: The JVM caches Integer objects between -128 and 127 in IntegerCache. Comparing two Integer objects with value 100 using == evaluates to true (same cached object). However, for values above 127 (e.g. 200), autoboxing creates distinct heap instances, so == evaluates to false. Coordinates and IDs should always use primitive int or .equals().
  9. How did your design handle the Day-4 Design Challenge without modifying existing tested classes?
    Answer: By strictly adhering to the Open-Closed Principle (OCP). We introduced EBike (overriding fee to return flat rate) and DeliveryVan (overriding fee with peak hour surge) as new child classes extending Vehicle. ParkingFacility naturally handled 5 floors because its constructor accepts a jagged array layout. TwoWheeler and Car remained 100% untouched.
  10. How does your system enforce garbage collection eligibility for departed vehicles?
    Answer: Active tickets are stored in a map during the vehicle's stay. Upon departure, exitVehicle() removes the ticket key from the map and nullifies the corresponding slot in the jagged array. Once the caller's local reference goes out of scope, the ticket object has zero active GC roots and is safely swept during the next minor GC cycle.
